# API 仕様書（設計案）

## 共通仕様

画面から利用する HTTP API のエンドポイント案。現在は未実装。アプリのプロセス内で起動するローカル API を想定し、`127.0.0.1` のみで待ち受ける。独立したバックエンドの配布や公開サーバーは設けない。採用する HTTP ライブラリ、ポート、起動・終了方法は実装前に決める。

- ベースパス：`/api`。以下のエンドポイントはベースパスからの相対パス。
- API 仕様バージョン：`1`。URL には含めない。
- 本文：JSON（`Content-Type: application/json; charset=utf-8`）。パスで指定したローカルファイルの読込はアプリ自身が行う。
- ID：UUID v4 文字列。日時：UTC の ISO 8601 文字列（例：`2026-11-14T12:00:00Z`）。
- エラー本文：`{"code": "文字列", "message": "利用者向け概要"}`。トーク本文、認証情報、外部サービスの生レスポンスは含めない。
- 共通ステータス：`400` 入力不正、`404` 対象なし、`409` 状態競合、`500` 内部エラー。各エンドポイント固有の応答は下記に記載する。
- ローカル API の呼び出し元制限と認証方式は未決定。実装前に決める。

## imports

利用者が選択した LINE の `.txt` ファイルを解析し、有効な行を SQLite に保存する。
不正な行は保存せず、新規・重複・不正の件数を返す。同じトークルームの再取込でも
既存の会話には追加せず、取込結果は記録する。

### `POST /imports`

保存済み LINE `.txt` を取り込む。

| リクエスト（JSON） | 型 | 内容 |
| :--- | :--- | :--- |
| `file_path` | `string` | 利用者が選択したローカル `.txt` の絶対パス |

| レスポンス（`201`） | 型 | 内容 |
| :--- | :--- | :--- |
| `import_batch_id` | `string (uuid)` | 取込履歴 ID |
| `imported_count` | `integer` | 新規メッセージ数 |
| `duplicate_count` | `integer` | 重複メッセージ数 |
| `invalid_count` | `integer` | 保存しなかった不正行数 |
| `errors` | `array<object>` | 不正行ごとのエラー |
| `errors[].line_number` | `integer` | 元ファイルの行番号。1 から数える |
| `errors[].message` | `string` | `xxx行目：パースが失敗したため読み取れませんでした。` |

重複はオプチャ名・書き込み時間・書き込んだ人の表示名・書き込み内容の組み合わせで
取込履歴をまたいで判定する。エクスポートにオプチャや書き込みの ID は含まれない。
本文内の改行を含む複数行の書き込みを一つのメッセージとして読み取る。
不正行ごとのエラーには元の本文を含めない。行の構造を判定できない場合に
どこから解析を再開するかは実ファイルを確認して決める。
ファイル不在は `404`、形式不明は `422`。文字コードと日時などの正規化方法は未決定。

## 要約

BE は利用者がダウンロード・配置した Codex CLI を実行して要約する。
アプリの配布物に CLI を同梱しない。OAuth 認証を画面のボタンから開始する方針とし、
CLI の指定・検出方法、呼出し引数・入出力・タイムアウト・認証期限切れ時の処理は別途設計する。

| リクエスト | 型 | 場所・内容 |

### `POST /summary-runs`

手動またはアプリ起動中の定期要約を開始する。処理を待たずに実行 ID を返す。
再要約では対象の既存要約を上書きする。定期処理は手編集済み要約を上書きせず、
利用者が明示的に再要約した場合に限り上書きする。再要約には対象範囲内の追加分も含める。
手編集済み要約の自動更新保護は、明示的な再要約後も維持する。
実際に使用したメッセージの内部 ID と、実行履歴・結果の要約との対応を保存する。
手動の要約処理が実行中なら、その回の定期実行は開始しない。
日付は取込・要約とも日本時間 0 時を境界とする。取込をまたいで同じオプチャ名・日付をまとめる。
定期処理の対象は日本時間で前日までとし、当日分は手動のみで扱う。
起動時に中断ジョブが残っていたら画面で再開するかを尋ね、利用者の選択なしに再開しない。
再開時は完了済みの要約単位を飛ばし、未完了の単位から処理する。
AI へ送信中だった単位は再送信前に利用者へ確認する。再開用エンドポイントは未決定。
要約の単位はオプチャ名・日本日付・午前／午後とする。
午前は日本時間 0:00 以上 12:00 未満、午後は 12:00 以上翌日 0:00 未満。
取込時も書き込み時刻で同じ区分に分類し、取込をまたいで同じ単位に集約する。
同名の別オプチャは区別できず、同じオプチャとして扱う制約を利用者に示す。
過去の関連情報も参考として渡す。
送信範囲には当日の対象に加え、参考にする過去の情報も含めて示す。
参考情報は同じオプチャ名の過去の日別要約を意味検索して選ぶ。
初期値は対象日の前日から過去 7 日間、重複を除いて最大 5 件。
期間・最大件数には実行開始時の設定を使い、当日・未来・別オプチャの要約を含めない。
類似度しきい値・順位付け方式・参考本文を含む入力量の制限は UI から変更できるようにする。
具体的な型・単位・初期値・許容範囲と、日別要約を指定するリクエストは未決定。
現行の `conversation_id` 一つによる指定は、取込をまたぐ午前／午後の集約に合わせて見直す。
参考検索が正常終了して近傍候補がなければ、参考なしで続行する。
LanceDB への接続・検索エラーの場合は要約を停止し、候補なしとは区別して失敗を返す。
検索反映が未完了の過去要約は参考候補から除外し、古いベクトルは使わない。
初回に複数の要約単位を処理する場合は古い順に進め、各単位の初回ベクトル生成が
成功してから次を処理する。失敗した単位では処理を停止する。

| リクエスト（JSON） | 型 | 内容 |
| :--- | :--- | :--- |
| `conversation_id` | `string (uuid)` | 対象会話 |
| `from_at`, `to_at` | `string (date-time)` | 対象期間 |
| `trigger` | `string` | `manual` または `scheduled` |

| レスポンス（`202`） | 型 | 内容 |
| :--- | :--- | :--- |
| `run_id` | `string (uuid)` | 実行履歴 ID |
| `status` | `string` | 初期状態。状態値は未決定 |

### `GET /summary-runs/{run_id}`

| リクエスト | 型 | 場所・内容 |
| :--- | :--- | :--- |
| `run_id` | `string (uuid)` | パス。実行履歴 ID |

| レスポンス（`200`） | 型 | 内容 |
| :--- | :--- | :--- |
| `run_id` | `string (uuid)` | 実行履歴 ID |
| `status` | `string` | 現在の処理状態 |
| `summary_ids` | `array<string (uuid)>` | この実行で作成・更新された要約 ID |
| `error` | `object \| null` | 失敗時のみ `code` と `message` |

要約単位の本文を SQLite に保存した時点で、その要約は完了とする。
初回ベクトル生成の成否は検索反映状態として別に扱う。
ベクトル生成に失敗しても保存済み要約を未完了へ戻さず、その単位で後続の一括処理を停止する。
実行全体の状態値と、検索反映状態を返すフィールドは未決定。

## 要約・分類

### `GET /summaries`

| リクエスト | 型 | 場所・内容 |
| :--- | :--- | :--- |
| `conversation_id` | `string (uuid), optional` | クエリ。省略時は全会話 |

| レスポンス（`200`） | 型 | 内容 |
| :--- | :--- | :--- |
| `items` | `array<object>` | 要約一覧 |
| `items[].id` | `string (uuid)` | 要約 ID |
| `items[].body` | `string` | 要約本文 |
| `items[].from_at`, `items[].to_at` | `string (date-time)` | 対象期間 |
| `items[].tag_ids` | `array<string (uuid)>` | タグ ID |
| `items[].is_bookmarked` | `boolean` | ブックマーク状態 |

### `PATCH /summaries/{summary_id}`

| 区分 | フィールド | 型 | 内容 |
| :--- | :--- | :--- | :--- |
| パス | `summary_id` | `string (uuid)` | 編集対象 |
| リクエスト JSON | `body` | `string` | 新しい要約本文 |
| レスポンス `200` | `summary` | `object` | 更新後の要約。`GET /summaries` の要素と同じ形 |

SQLite への本文保存が成功した場合は、ベクトル生成が失敗しても本文保存を取り消さない。
本文の保存成功と検索への反映「未完了」を分けて画面に返す。具体的な応答フィールドは未決定。
手編集では保存済みの AI 原文を変更せず、自動更新保護を設定する。
新規要約の作成では初回ベクトル生成まで処理する。既存要約の本文変更でも
変更した要約自身を再ベクトル化する。失敗時は検索反映を未完了として再生成可能にする。
その要約を参考に作られた後続日の要約は、本文・ベクトルとも連鎖更新しない。

### AI 原文への復元（エンドポイントは未決定）

保存済みの最新 AI 生成要約を表示用本文へ戻す。外部 AI は呼び出さず、検索反映は未完了とする。
復元した要約自身を再ベクトル化し、復元操作で自動更新保護は解除しない。
複数世代を保持できる内部構造とするが、過去世代を選ぶ一般向け API・UI は設けない。
内部の保持世代数と削除条件は未決定。

## 検索

### 検索データの再生成（エンドポイントは未決定）

SQLite に保存済みの表示用要約本文からベクトルを生成する。要約の再生成や外部 AI 呼び出しは行わない。
失敗した場合も要約本文を保持し、検索への反映を「未完了」として再実行できるようにする。
進捗取得、全件・差分の範囲、同時実行制御は未決定。

### `GET /summaries/search`

意味検索を行い、SQLite の要約本文を返す。

| リクエスト | 型 | 場所・内容 |
| :--- | :--- | :--- |
| `query` | `string` | クエリ。空文字は不可 |
| `limit` | `integer` | クエリ。上限は未決定 |

| レスポンス（`200`） | 型 | 内容 |
| :--- | :--- | :--- |
| `items` | `array<object>` | 検索結果 |
| `items[].summary_id` | `string (uuid)` | 要約 ID |
| `items[].body` | `string` | 要約本文 |
| `items[].rank` | `integer` | 1 から始まる順位 |
| `items[].score` | `number` | 類似スコア |

検索反映が未完了の要約は結果から除外し、古いベクトルを使わない。
要約一覧・詳細では SQLite の本文を表示できる。モデル未準備または検索用データ未構築は `409`。
スコアの尺度はモデル決定後に定義する。

## 設定

### `GET /settings`

| 区分 | フィールド | 型 | 内容 |
| :--- | :--- | :--- | :--- |
| リクエスト | 本文なし | `null` | 入力なし |
| レスポンス `200` | `destination` | `string` | Codex の送信先 |
| レスポンス `200` | `has_credentials` | `boolean` | 認証情報の登録状態 |
| レスポンス `200` | `data_directory` | `string` | 保存先の絶対パス |
| レスポンス `200` | `embedding_model` | `string \| null` | 未決定・未設定なら `null` |
| レスポンス `200` | `summary_context_days` | `string` | 参考要約を探す日数。正の整数の十進文字列。初期値 `"7"` |
| レスポンス `200` | `summary_context_max_summaries` | `string` | 参考要約の最大件数。正の整数の十進文字列。初期値 `"5"` |

認証情報の中身は返さない。

### `PATCH /settings`

| 区分 | フィールド | 型 | 内容 |
| :--- | :--- | :--- | :--- |
| リクエスト JSON | `settings` | `object<string, string>` | 秘密情報を含まない設定名と値 |
| レスポンス `200` | 設定 | `object` | `GET /settings` と同じ形 |

`summary_context_days` と `summary_context_max_summaries` を更新できる。
値は正の整数の十進文字列とし、不正な入力は `400` として変更を保存しない。
変更は次に開始する要約・再要約から適用し、実行中・保存済みの要約には遡って適用しない。
この二つの設定の上限値、その他の許可する設定名と値の規則、および認証情報の登録方法は未決定。
類似度しきい値・順位付け方式・AI 入力量と日数・件数の上限を UI から更新できる方針とする。
具体的な追加フィールド・型・単位・許容範囲はモデルと検索方式の決定後に定める。
